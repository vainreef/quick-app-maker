# 创意需求访谈规范（Progressive Requirement Discovery）

## 核心目标

把用户最初的一个朦胧想法，通过**“逐轮递进提问、每轮把最新理解同步写入应用 `README.md`、最终通俗完整复述并经用户确认‘对’”**的闭环机制，收敛成一份可落地、可验证、经过用户亲自认可的 V1 产品合同。

**严禁在用户确认前自作主张开工，严禁向用户询问或透露任何技术黑话。**

---

## 阶段流水线

```text
第一问启迪 
  ↓
用户给出首个实质想法 → 立即在当前工作目录创建项目目录与 living `README.md`
  ↓
逐轮深入提问 ⇄ 每轮先更新 `README.md`，再抛出下一问（围绕画面、操作、风格、边界）
  ↓
用户主动收口 / 需求要素完整
  ↓
通俗完整复述整个产品体验，结尾询问：『我理解的是这样，对吗？』
  ↓
用户明确回复确认（如“对”、“就是这样”）→ 更新 README 状态为“需求已确认”
  ↓
正式进入工程实现（qam create 与业务编码）
```

---

## 第一问起手式

当用户尚未展开具体想法，或仅给出一句非常宽泛的意图时，使用：

```text
你想做一个什么样的 App？可以先随意描述你脑中的画面、玩法、感觉或日常场景。
```

---

## 核心循环（每轮必跑）

每次收到用户的一句回复，Agent **必须严格按以下顺序执行**：

1. **阅读应用当前的 `README.md`**；
2. **在 `README.md` 中同步更新**：
   - 用户需要什么（Wants）；
   - 用户目前不需要/省略什么（Exclusions）；
   - 打开第一眼与核心操作流；
   - 风格质感与暂定名称；
   - 记录本轮创意变更；
3. **保存 `README.md` 文件**；
4. **判断是否触发收口**：
   - 若未收口：**每次只问一个最自然、最核心的问题**（最多合并两个强关联问题），引导用户深入；
   - 若已触发收口：停止新增提问，进入“通俗完整复述”。

---

## 逐层递进提问阶梯（Progressive Question Ladder）

根据用户当前的回答重点，自然挑选最需要明确的一个缺口：

### 第 1 层：核心愿景与画面
- 你脑中最想做的是一个什么 App？
- 你想象它打开时是什么画面？这个想法里最让你兴奋的是哪一部分？

### 第 2 层：使用人群与时机
- 你想主要自己用，还是也希望身边朋友、家人或同事也能用？
- 大家通常会在什么时候打开它？是每天都用，还是特定时刻或遇到事情时才打开？

### 第 3 层：打开后的体验（第一眼与核心闭环）
- 打开后第一眼最应该看到什么？
- 用户的第一步动作通常是点哪里、输入什么或翻开什么？
- 接着你希望发生什么？最后得到什么结果或保存下什么？
- 哪个瞬间最应该让用户觉得“做成了 / 很满意”？

### 第 4 层：风格、材质与仪式感
- 怎样让这个过程更有趣、更漂亮或更有仪式感？（例如：是羊皮纸火漆印章、星辰胶囊、深色典雅手帐，还是极简清爽卡片？）
- 有没有某个小动效、特殊排版或特定文案，能让它特别有记忆点？

### 第 5 层：第一版取舍（边界划分）
- 第一版最核心、绝对不能少的三件事是什么？
- 有哪些功能你觉得很棒，但第一版可以先明确省略、以后再加？
- 哪些体验一旦改变，就不是你心里想做的那个 App 了？

### 第 6 层：数据与日常行为（用生活化语言提问）
- 记录的内容只要保存在这台电脑里随时打开看，还是有其他特殊想法？（说明：桌面版默认安全保存在本地电脑，不联网、绝不泄露隐私）
- 出现内容为空（首次打开）或者没填全时，希望界面给出怎样贴心的提示？

### 第 7 层：产品气质与中文命名
- 你想给它起个什么好听的中文名字？（如未定，可提供 2~3 个富有诗意或契合主题的名字供点选；英文目录名由 Agent 内部自动推导，严禁打扰用户）。
- 希望它给人的感觉是安静、庄重、专业、可爱、温暖，还是有趣？

### 第 8 层：完成标准（怎样算做好）
- 你亲自在电脑上试用时，做到哪几件事你就会觉得“这就是我想要的，做好了！”？

---

## 收口信号检测（Stop-signal Detection）

用户随时可以在任意一轮结束访谈，常见收口信号：
- “就是这样”、“差不多了”、“就这些”；
- “按这个方向来吧”、“开始吧”、“可以做啦”；
- “第一版先这样，后面再改”、“其他你决定”。

收到收口信号，或当核心流程、第一眼、数据、风格与边界均已清晰时，**立即停止新增提问**，进入最终确认。

---

## 通俗完整复述与确认模板（Plain-Language Confirmation）

Agent 将 `README.md` 中的全部内容，转化成一段不带任何技术名词、纯粹聚焦于“用户真实体验”的完整复述：

```text
我把你的想法整理成了完整的方案，你看是不是这样：

【要做一个什么样的 App】
[用 1~2 句话通俗生动地总结应用定位与核心价值]

【使用体验与核心操作】
1. 打开第一眼：[描述用户启动应用第一眼看到的画面与氛围]
2. 核心操作：[描述用户点击什么、填写什么、如何保存]
3. 仪式反馈：[描述保存或完成时的动效、反馈与结果呈现]
4. 浏览回顾：[描述如何查看历史记录、翻阅卡片或展开详情]

【第一版包含的要点】
- 需要的：[要点 1]、[要点 2]、[要点 3]
- 明确先省略的：[省略项 1]、[省略项 2]

【视觉风格与中文名称】
- 风格气质：[如深黑胡桃木质感、金色火漆印章、庄重典雅卡片]
- 暂定名称：[中文应用名]

【怎样算做好】
- [列出 2~3 条用户可感知的验收标准]

这是我对你想法的完整理解。我理解的是这样，对吗？
```

---

## 准出与动工铁律（Transition to Implementation）

1. **绝对停步等待**：发出确认复述与“我理解的是这样，对吗？”后，Agent **必须结束当前发言，从容等待用户回复**；
2. **严禁越权创建**：在用户明确回答“对”、“是的”、“就是这样”、“按这个做”之前，**严禁执行 `qam create`，严禁编写任何代码**；
3. **确认即刻动工**：
   - 收到用户确认后，先将项目 `README.md` 的状态更新为 `需求已确认`；
   - 输出简明确认句：
     > “明白，方案已正式锁定！我现在为你全自动完成工程创建、业务编写与测试验收，完成后直接在屏幕上为你打开应用体验。”
   - 随后静默执行 `qam create`、编写 HTML/JS/CSS 真实业务、运行 `qam test` 验收并通过 `qam dev` 直接拉起窗口供用户试用。
