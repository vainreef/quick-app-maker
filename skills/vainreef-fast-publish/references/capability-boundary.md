# 技术限制与能力边界规范（Capability Boundary & Projection）

## 核心定位：八字契约

Quick App Maker 的核心能力边界由以下八个字彻底锁定：

> **“免费、本地、个人、通用；固定技术栈；Microsoft Store 纯桌面应用。”**

所有需求必须投影到这个盒子里。**Quick App Maker 绝不是全栈 Web 网站生成器，它是一个纯粹的本地桌面应用框架。**

---

## 核心边界矩阵（红线对照表）

| 维度 | Fast Mode 本地桌面铁律（合法范围） | ❌ 绝不支持的越界行为（Hard Boundary 硬性阻断） |
| :--- | :--- | :--- |
| **后端与服务器** | **自建服务器边界完全为空！**<br>所有核心计算、业务逻辑 100% 在本地 Electron 进程内运行。没有 Backend，没有自建 Node 服务端，没有云函数。 | **自建后端服务、自建数据库服务器（MySQL/MongoDB等）、远程任务队列、微服务、集中式后端 API** |
| **账号与登录体系** | **单机个人免登录！**<br>无需注册，无需登录，打开即用。数据 100% 归属于当前电脑的使用者，一人一机。 | **手机号登录、短信验证码、微信/扫码登录、用户名密码注册体系、JWT 鉴权、多端用户体系** |
| **数据与存储** | **本地离线优先！**<br>数据仅通过 Electron 安全 IPC（`window.qam.saveState / loadState`）保存在本机独立 JSON 文件中，退出不丢失。 | **云数据库（Firebase/Supabase等）、云端备份、多端实时同步、数据上传到集中式服务器** |
| **网络与外部服务** | **网络 $\neq$ 后端！**<br>允许客户端通过 `fetch` 直接请求无需鉴权的**公网公开 API**（如公开天气、公开汇率、公开诗词），或由用户在应用“设置”中**填入用户自有的 API Key**（如个人 OpenAI / DeepSeek Key）。 | **由开发者/项目方统一购买额度并中转调用、在客户端代码中硬编码隐藏私钥、自建代理服务器、统一计费系统** |
| **域名与网站** | **应用逻辑 100% 独立于网站！**<br>纯本地应用，无需域名。仅在商店发布时按需提供静态隐私声明或代码托管页面。 | **必须依赖特定 Web 域名、必须通过特定网页回调登录、依赖 Web 远程管理后台** |
| **商业化与价格** | **完全免费！**<br>应用在微软商店与本地均为 Free 免费工具。 | **付费购买、应用内内购（IAP）、付费订阅、接商业广告 SDK、支付网关对接** |
| **权限与系统访问** | **普通桌面沙箱权限！**<br>标准桌面窗口、系统文件选择器（打开/保存文件）、本地存储。 | **内核驱动、全局键盘/屏幕监听、管理员提权（Administrator/UAC）、注入其他进程、系统深层拦截** |
| **应用类型** | **通用个人效率与生活工具！**<br>记事、日记、备忘、个人账本、本地文件处理、效率小工具、公开信息查询、个人学习创作。 | **金融交易、医疗诊断、网络赌博、强版权依赖素材库、必须企业营业执照的特殊合规资质领域** |

## 关键概念厘清：网络不等于后端

**“能联网”不代表“有后端”。必须严格区分数据流向：**

### 1. 合法的客户端直连模式（允许）
```text
客户端 Electron App ──(HTTPS 请求)──> 第三方公网开放平台
```
- **公开信息查询**：用户输入“北京”，客户端直接调用公开的天气 API 显示气温；
- **用户自备凭证**：用户想用 AI 辅助润色日记，用户在应用设置页填入自己的 API Key，客户端直接带着该 Key 访问 AI 服务商官方接口，Key 仅保存在本机。

### 2. 非法的自建服务端模式（严禁）
```text
客户端 Electron App ──> 自建服务器 (Node/Go/Python) ──> 远程数据库 / 业务中转
```
- 只要出现“需要一台服务器来存数据”、“需要服务器来发短信验证码”、“需要在服务器鉴权”，**立即触发 Hard Boundary 拦截！**

## 本地化降解协议（Fast Mode Projection）

当用户提出包含**“服务器、手机号登录、云同步、多端共享”**等超出边界的需求时，**Agent 绝对严禁迎合用户并假装编写服务端代码，也严禁直接冷冰冰拒绝！**

**正确做法**：必须当轮进行**本地化降解（Fast Mode Projection）**，说明保留的核心价值，并用生活化语言向用户提出转为“纯本地单机免登录版”的替代方案。

### 常见场景降解对照表

| 用户原始越界需求 | 触发项 | 本地化降解方案（Fast Mode Projection） |
| :--- | :--- | :--- |
| **手机号登录与短信验证**<br>“要能用手机号发验证码登录，换手机也能用” | 账号体系、短信网关、集中式服务器 | **免登录纯单机版**：无需注册与手机号，打开直接使用；所有数据完全保存在当前电脑本地，极速响应且绝无隐私泄露风险。 |
| **云同步与多端备份**<br>“我在办公室记的东西，回家电脑和手机也能看到” | 云数据库、远程同步服务、用户鉴权 | **本地导出与便携备份**：提供一键“导出备份文件”和“导入恢复”功能，用户可通过网盘或 U 盘自由迁移数据文件。 |
| **AI 智能功能需要服务器**<br>“帮我集成大模型，但我不想买服务器” | 隐藏密钥、代理中转、计费服务 | **自备 Key 本地直连**：提供精美的 API 设置界面，引导用户填入自己的 API Key（如通义千问/DeepSeek），客户端直接调用，零服务器成本。 |
| **多人共享记账 / 团队协作**<br>“我和老婆一起记账，两个人手机实时同步” | 多人协同、实时 WebSocket、权限体系 | **本地家庭独立账本**：做成单机精美手帐账本，支持按不同家庭成员打标签，数据保存在本机。 |

---

## 降解引导标准话术（User-Facing Language）

当检测到用户想法触碰技术边界时，在当轮访谈中直接使用以下通俗模板进行引导：

```text
你想要的这个功能重点在于：[核心体验，例如随时记录重要事情并安全保存]。

其中 [手机号登录 / 服务器云端同步 / 短信验证码] 会需要额外搭建长期的远程服务器、短信网关和网络账号体系，这会让应用变得臃肿且产生持续的云端费用。

我们当前的 Windows 桌面版本，最推荐的优雅做法是做成【纯本地单机版】：
1. 保留全部核心体验：[说明保留的功能与仪式感]；
2. 打开即用，完全免登录，没有繁琐的验证码；
3. 数据 100% 保存在你自己的电脑本地，速度极快，而且绝不会有任何个人隐私被上传到外部云端；
4. 以后需要换电脑时，支持一键导出/导入数据文件。

我们第一版就按这个“安全、纯净、无云端打扰”的本地单机方案来为你制作，你看这样好吗？
```
