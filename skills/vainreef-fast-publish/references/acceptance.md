# 应用验收边界

适用于创建、修改及修复应用。不要求模型具有多模态能力，不接管用户物理桌面。这里规定交付证据，不教授具体界面实现。

## 1. 能力与证据分层

| 检查 | 证据与边界 |
| --- | --- |
| 源码与模板检查 | 记录实际断言；出现某个 API 字符串不代表该功能已执行 |
| 无头挂载 | 现有 `qam test` 使用浏览器和模拟 `window.qam`；成功只说明被检查页面挂载，跳过仍记为跳过 |
| 隔离业务检查 | 记录具体输入、动作和断言；模拟保存仅证明前端调用，存储逻辑需使用独立测试目录另行验证 |
| 无头截图 | `qam screenshot` 渲染应用界面并生成 PNG，不是用户桌面或真实 Electron 桥接的验证 |
| 视觉评价 | 纯文字模型和 OCR 不承担视觉判断；有图像能力且实际读取时可补充，用户最终确认 |
| 真实体验 | 用户亲自验证系统选择器、操作手感、保存及关闭重开；Agent 不读取正式用户数据或伪造试用 |

根据宿主实际提供的能力选择分支，不要求用户证明模型能力。没有直接图像输入时按纯文字分支执行。截图文件存在、尺寸正确或 OCR 正确均不升级为视觉通过。

## 2. 按业务状态检查

从已确认 README 推导最小场景：空状态、典型有内容状态、核心录入、相关错误状态。图片应用包含带图预览和带图记录；长内容应用包含长文字与支持的小窗口。仅检查空页面不足以覆盖有内容布局。

- 程序证据关注实际可检查的元素存在、可达性、图片解码、溢出或错误反馈；源码推断与运行断言分开记录，不宣称这些客观检查等于精美。
- 长内容和图片应有适用的布局或完整查看方式，弹窗操作应保持可达；逐项对照已确认的体验，不默默删减需求。具体排版、风格和像素值由应用决定。
- 只在工作区隔离测试中使用合成文字和测试图片。可补充应用测试并经 `qam test` 运行；截图使用现有 `--eval` / `--click`，等待对应状态及图片就绪。勿为截图临时篡改业务初始状态或把演示数据注入正式窗口。
- 测试和截图串行执行，不直调底层 Electron，不申请桌面权限。临时数据、诊断脚本放工作区 `.cache/` 并清理；可重复回归用例可保留在应用测试目录。
- 场景驱动失败就记录该场景未验证，调整已有测试方式或交用户确认；不得回退到空状态后宣布整项通过。

## 3. 故障验证与数据保护

- 修复围绕原失败路径增加回归证据，如图片导入验证“读取 → 解码 → 压缩 → 预览”，而非仅复跑模板断言。原始 CSP 报错、最小复现、修复前后结果可支持归因；搜索结果只支持机制解释。
- 读取失败与首次无数据分开处理。保留原文件，防止空状态覆盖；明确错误状态和重试入口，待成功读取或用户明确选择处理方式后再恢复正常写入。
- 图片处理应有忙碌状态；保存不抢在处理完成前；连续换图时旧异步结果不覆盖新选择；保存和删除等写入应避免冲突。
- 错误提示在对应操作位置可见，并保留脱敏的阶段、message、stack、cause（存在时）。别只赋值一个未渲染的状态变量。

## 4. 记录与用户交付

在应用 README 验证区记录：场景、方法、结果（通过/失败/跳过/未执行/待用户确认）、证据路径和待确认项。模板检查、挂载、业务、视觉和真实持久化分别记录。

已执行检查存在未决失败时先排查，不宣布成功；缺少视觉能力本身不是失败。恢复应用窗口后，向用户简短说明：“程序检查已完成的范围是……；截图已整理，外观与真实选图、保存重开请你试用确认。”由用户反馈更新验收状态，不把“已启动”写成“用户体验通过”。

## 5. 现有工具范围

本文件是执行与报告要求，不代表 CLI 已内置业务场景生成、像素布局评估、图片导入回归或完整持久化测试。只使用命令手册与当前实现支持的入口；按任务补充的检查也需实际运行并记录，不发明参数或把计划检查写成已完成。
