# Vainreef Fast Publish V2

使用仓库现有入口完成 Windows 应用制作和 Microsoft Store 发布。保留已经跑通的页面操作与浏览器流程，不临时重写发布控制器。

## 选择模式

根据用户当前目标只进入一个模式：

1. **创建应用**：新建 Windows 桌面应用。
2. **修改应用**：调整已有应用的功能、数据或外观。
3. **准备发布**：整理名称、程序包、文案和图片。
4. **继续发布**：根据当前状态处理尚未完成的商店阶段。

按需读取资料：

- 创建或修改应用：[需求访谈](references/discovery-interview.md)

- 已经遇到过的页面、打包问题和图片交付：[发布手册](references/store.md)
- 国内网络和工作区缓存：[网络与缓存](references/network.md)

## 共同约束与技术边界（八字契约）

Quick App Maker 恪守 **“免费、本地、个人、通用”** 八字契约，绝不越界（详见 [能力边界规范](references/capability-boundary.md)）：

- **自建服务器边界为空**：自建后端服务边界为 0。严禁自建 Backend、数据库服务器或微服务，所有核心计算与状态逻辑 100% 运行在本地 Electron 进程内。
- **单机个人免登录**：严禁手机号登录、短信验证码、用户注册登录系统或集中式多端同步；应用定位为纯单机个人工具，打开即用。
- **本地离线优先**：严格使用 `window.qam.saveState()` 与 `window.qam.loadState()` 在本地持久化 JSON 数据，严禁向任何云端上传用户个人数据。
- **网络不等于后端**：仅允许客户端纯 HTTPS 直连公网公开 API 或由用户在设置中填写用户自有 API Key 直连服务商，客户端不得硬编码项目方统一私钥或代充额度。
- **本地化降解铁律（Fast Mode Projection）**：当用户提出包含后端、服务器、手机号登录或云同步需求时，**严禁迎合或构思服务端**，必须当轮使用生活化语言说明原因，引导其降解为“安全纯净的本地单机免登录版”。
- Windows 命令统一通过 `bootstrap/qam.cmd`；工作区中的便携 Node、Git、npm 和缓存保持隔离。
- macOS/Linux 使用仓库现有入口 `node bin/qam.mjs`；浏览器自动兼容 Edge 与 Chrome（macOS 默认优先使用系统 Google Chrome 或 Edge）。
- 自动识别工具仓库、工作区和应用目录（当应用位于外部驱动器或项目目录时，自动以应用上层作为 workspace 挂载，并继承工具链核心资产与 makemsix 原生编译器）。英文目录名由 Agent 内部推导，不向普通用户询问。
- 生产打包跨平台原生支持：macOS/Linux 下通过微软官方原生 `makemsix` 确保 64KB 块物理对齐，Windows 下通过 `@microsoft/winappcli` 打包。
- 同一个应用的开发、打包和 Store 操作严格串行。
- `qam dev` 是长驻进程；Agent 在后台启动并直接向用户展示窗口。
- 页面故障处理只使用发布手册中已经记录的做法。

## 创建或修改应用

### 阶段 1：逐步递进需求访谈与 living README 记录（强制阻断）
每个新应用必须经历完整的逐步创意访谈（详见 [需求访谈规范](references/discovery-interview.md)）：
1. **第一问启迪**：`你想做一个什么样的 App？可以先随意描述你脑中的画面、玩法、感觉或日常场景。`
2. **第一段想法即立项建档**：用户给出首个实质想法后，Agent 内部推导暂定 slug，立即在工作区创建 `<app-slug>/README.md`（按 `project-readme-template.md` 初始化）。
3. **逐轮深入与实时写 README**：
   - 每次收到用户回答后，**必须先更新该项目目录下的 `README.md`**（记录：需要什么、暂不需要什么、第一眼、操作流程、风格质感、字段与边界）；
   - 保存 `README.md` 后，**每轮只提一个最关键的体验问题**抛给用户，引导其自然深入；
   - 严禁向用户询问任何代码、架构或技术黑话，全程使用生活化语言。
4. **收口信号与通俗完整复述**：
   - 识别用户收口信号（“差不多了/就这些/开始吧”），或要素齐备时停止新增提问；
   - 用通俗语言向用户输出完整产品理解复述（定位、打开第一眼、核心操作、仪式反馈、第一版边界、风格与中文名）；
   - 结尾必须严格询问：**`我理解的是这样，对吗？`** 并结束发言等待用户回复。
5. **用户确认方可动工（准出铁律）**：
   - 在用户明确回复“对/是的/就按这个做”之前，**严禁执行 `qam create`，严禁编写任何代码**；
   - 用户确认后，更新 `README.md` 状态为“需求已确认”，才正式启动后续工程创建与业务编写。

### 阶段 2：创建应用与业务落地
1. 执行 `qam create --name "<中文名称>" --slug <app-slug>` 生成工程骨架；
2. 必须紧接着修改 `src/renderer/index.html`、`app.js`、`styles.css` 实现用户的真实业务，严禁交付空骨架；
3. 必须通过 `window.qam.loadState()` 与 `window.qam.saveState()` 实现本地安全数据持久化，界面与主进程字段对齐。

### 阶段 3：自动化验收、视觉自检与首版拉起试用
1. 运行 `qam test .\<app-slug>` 进行契约与无头真机挂载自动化验收（自动检验 `#app` 成功脱去 `v-cloak` 且无任何控制台/模板运行时异常）；
2. **视觉自查第一铁律（视觉防呆）**：`qam test` 仅检验无头挂载和脱掉 `v-cloak`，绝不代表界面视觉可用！在拉起 `dev` 交付用户试用或生成商店素材前，**必须先执行 `qam screenshot .\<app-slug>` 捕获真机截图进行视觉自检**：
   - 核心交互按钮是否可见（如封面/首页有无翻开、开始按钮，严禁将按钮置于默认隐藏容器内）；
   - 色彩对比度是否清晰（深色背景必须使用浅色字，浅色纸面使用深色字，严禁深色叠深色导致标题或空状态肉眼不可辨）；
   - 界面是否纯净专业（严禁将“已读取”、“加载成功”等底层技术调试字样直接暴露在首屏）；
3. 验收与视觉自检通过后，在后台异步启动 `qam dev .\<app-slug>` 直接将应用窗口拉起到用户屏幕前供其试用体验；
4. 向用户汇报核心功能已做好，保持窗口开启，收集修改意见；
5. **故障响应与恢复流程**：若用户反馈窗口空白、报错或窗口意外关闭，严禁自行手写临时测试脚本（如 verify-render、probe）；排查并修改源码后，唯一合法闭环是：`修改源码 → 运行 qam test 确认挂载通过 → 重新后台启动 qam dev 拉起窗口 → 简明询问用户是否恢复正常`。

## 发布触发条件与五步人机协同标准流程

只有用户明确提出上架、发布、打包或继续 Store 提交时进入发布流程。发布严格遵循五步协同流水线：

### 第 1 步：登录与保留名称协同（CDP 自动捕获与透明度契约）
1. **工作区锁前置协同**：启动发布前，**必须先停止后台长驻的 `qam dev` 任务**，等待 2~3 秒释放工作区互斥锁（`WorkspaceLock`），杜绝 `workspace is busy` 报错；
2. 执行 `store launch --app .\app-slug` 拉起独立隔离浏览器沙箱（Windows 默认原生 Edge，macOS 默认 Chrome）；
3. **提前向用户告知自动化采集机制（透明度契约）**：明确说明“你在浏览器中点击保留后，工具会通过已建立的本地调试通道自动读取新生成的 Product ID 与微软官方开发者身份（Identity/Publisher），无需手动复制粘贴任何代码”；
4. 提示用户在弹出的浏览器中登录微软开发者账号，进入「新产品」$\rightarrow$「MSIX 或 PWA 应用」输入应用名称并亲自保留；向用户提供建议名称与备选名；
5. **`product/NotFound` 异常应对**：若页面提示“抱歉，我们找不到该页”，告知用户因独立沙箱无历史 Cookie，未登录或租户错位会导致该安全脱敏提示；指引用户点击右上角登录或访问应用大厅 `/apps-and-games/overview` 即可恢复；
6. 提示用户保留成功后在聊天框回复“我保留好了”，Agent 结束发言等待用户回复；
7. 收到确认后，执行 `store reserve --app .\app-slug --name "<应用名称>"`，自动从浏览器当前页面与 `/identity` 表格中提取凭据并回填工程清单。

### 第 2 步：材料全面盘点与来源协同
1. 向用户完整列清 Microsoft Store 上架所需的全部材料清单与规格：
   - 详细说明正文（几百字）；
   - 简短描述（200 字以内的精炼卖点）；
   - 3 个核心产品功能条目；
   - 3~5 个搜索关键词；
   - 1~4 张 1366x768 真机操作界面截图；
   - 1 张 1:1 酷图主徽标（1080x1080）；
   - MSIX 程序包图标集合与 runFullTrust 离线权限理由声明（详见 `references/store.md`）；
2. 主动询问用户材料来源意向（方案 A：Agent 全自动生成；方案 B：用户自备；方案 C：混合模式）；
3. 等待用户确认方案后，再开始执行真实素材生成与整理。

### 第 3 步：真机素材生成、交互弹窗与用户检视确认
1. 严禁使用脚手架纯色占位图；必须使用官方命令 `qam screenshot .\app-slug` 自动捕获 1366x768 高清截图并设计 1080x1080 酷图与全套图标；
2. **多视图截屏规范**：如需截取子视图（如列表页、记录表单、设置弹窗），**绝对严禁临时修改业务源码**，统一使用 `qam screenshot .\app-slug --output <path> --eval "<code>"` 或 `--click "<selector>"` 进行无侵入式捕获；
3. 素材统一整理在 `store-submission-assets` 文件夹，**全部采用纯中文清晰命名与纯文本 `.txt` 格式**（如 `00_完整文案与亮点特性说明.txt`、`01_应用主界面高清截图_1366x768.png`、`02_1比1酷图主徽标_1080x1080.png` 等）；
4. 必须通过交互式任务指令拉起文件管理器（Windows 资源管理器 / macOS Finder），置顶展示在用户屏幕前；
5. 向用户逐一说明每个素材的作用与规格，提醒用户核对确认；
6. 明确告知用户：**素材核对无误后，请在聊天框回复我说『确认素材』或『继续』，我接着为您全自动填报并上传！** 结束发言等待用户确认。

### 第 4 步：按需精准生效与全自动流水线接力
1. 用户回复“确认素材”或“继续”后，执行 `package --profile store` 生成 64KB 块物理对齐的正式 MSIX 安装包，并执行 `store preflight` 验证；
2. 执行 `store discover --app .\app-slug`，自动识别产品概览页中的 `<he-button data-l10n-key="Start_Submission">`（开始提交），点击生成 `Submission 1` 草稿并解析六大阶段路由；
3. **文案单一真理源自动同步**：底层自动化工具 `loadDesired` 已内置资产嗅探，会自动将第 3 步整理在 `store-submission-assets/00_*.txt` 中的正式中文文案注入 `desired-state.json`，确保填报的是用户确认的真实文案；
4. 依据状态按需精准执行单阶段填报（`store apply --phase <phase>`），严禁全量重复轮询已有绿标模块；若遇到表单保存按钮因微前端网络瞬态隐藏（`ng-hide` 或“我们在加载此页面时遇到问题”），自动执行 `page.reload()` 重新挂载表单；
5. **告警零容忍阻断铁律（Zero Unhandled Warning）**：执行日志中凡出现 `failed`、`not found`、`has-error`、`REQUEST_FAILED`，即使 CLI 返回码为 0 或概览显示 Complete，也一律视为存在假阳性，必须就地回读核实关键字段（如价格阶层、分类、隐私文本、截图状态），严禁直接汇报成功；
6. 填报完成后，执行 `store verify` 进行一键总体验收。

### 第 5 步：人工最终审核与提交
1. 验证通过（6 大模块全绿标 Complete）后，Partner Center 页面上的「提交进行认证」按钮自动高亮可用；
2. 提示用户在浏览器中做最后的人工核对，并亲自点击「提交进行认证」。

## 故障恢复与关键铁律

1. **CLI 进程确定性退出与工作区锁死锁防御**：`bin/qam.mjs` 在 dispatch 结束后必须显式调用 `process.exit(code ?? 0)`，严禁因 Playwright CDP 底层句柄未释放导致进程悬挂并锁死 `WorkspaceLock`；
2. **阶段切换互斥锁协同**：进入 `store` 发布命令前必须停止 `dev` 任务释放锁；
3. **外置驱动器与跨工程寻址**：自动将目标 App 父目录推导为 `workspace`，通过 `QAM_TOOLCHAIN_ROOT` 跨目录寻址原生 `makemsix` 编译器；
4. **零后端与单机个人免登录铁律**：严禁搭建任何自建服务端或账号系统，所有状态本地离线持久化；
5. **两级提交草稿生命周期**：产品刚保留时仅处于“产品草稿态”，必须点击「开始提交」生成“提交版本草稿态”后方可填报 6 大模块；
6. **Windows PowerShell 语法规范**：严禁使用 `&&` 分隔符，图片处理优先使用 Node 脚本。

## 完成口径

应用完成以现有测试通过、真实窗口可操作并已交给用户试用为准。Store 准备完成以当前发布流程执行完毕、现有总检通过以及用户确认图片为准。不要把新增推断或尚未运行的检查写成完成证据。
